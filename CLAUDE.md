# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

VibeDxf is a small C# / WPF 2D DXF viewer with element-to-element distance measurement, targeting `net10.0-windows`. The drawing is rendered with Direct3D 11 and Direct2D through Vortice.Windows (`Vortice.Direct3D11`, `Vortice.Direct2D1`, `Vortice.D3DCompiler`). These are the only NuGet packages; don't add others without a good reason. See [README.md](README.md) for user-facing controls and the supported/unsupported DXF feature scope.

## Packaging and releases

See [RELEASING.md](RELEASING.md) for the release procedure, versioning, local installer builds, GitHub Actions publication, icons, runtime requirements, and verification/recovery. Keep these maintainer details there and keep README.md user-facing. Releases are framework-dependent Windows x64 builds: never bundle, download, or install the .NET runtime automatically.

## Commands

```powershell
# Build
dotnet build .\VibeDxf.sln -c Release

# Run the viewer (optional DXF path argument)
dotnet run --project .\src\VibeDxf.csproj -- "path\to\file.dxf"

# Run xUnit checks (also discoverable in Visual Studio Test Explorer)
dotnet test .\Tests\VibeDxf.Checks.csproj -c Release

```

Use Test Explorer to select individual named cases, or `dotnet test --filter "DisplayName~circle center / center"`. The 113 original offline checks are xUnit theory cases with string-only discovery data; an extra test ensures the catalog matches the scenario checks. Two public fixture cases always run from `Tests/Fixtures/Public`, checking exact supported/unsupported counts and GPU uploads. See its README for provenance and coverage. Runtime setup is rebuilt for each case; rendering cases run on dedicated STA threads. A shared collection fixture writes the HTML report at the end, with parallel execution disabled to keep GPU capture and report output deterministic.

## Architecture

The desktop app (src/VibeDxf.csproj, namespace VibeDxf) contains application UI and references the one src/VibeDxf.Wpf library (namespace VibeDxf.Wpf). That library owns loading, immutable prepared documents, text/geometry/measurement and DxfView. DrawingRenderer, DxfViewport interaction engine, native host and mutable loading builders are internal. See [current integration](docs/NUGET-SINGLE-INTEGRATION.md). The notes below describe internal implementation details:

- [Geometry.cs](src/VibeDxf.Wpf/Geometry.cs) — `Curve` (a single record representing both line segments and arcs; `Radius == 0` means line) with analytic `Closest(Point)` and `Curve.Distance(a, b)` returning a `ClosestPair`. A straight curve's `Extent` (`Segment`, `Ray`, `Infinite`) sets its parameter range `TMin..TMax`; for RAY/XLINE, `End` is only a unit direction handle and `Bounds` holds just the base point, so Fit stays finite and picking skips the bounds prefilter. Also `DxfEntity` (kind, layer, handle, list of curves). Every entity — including polylines with bulges — is decomposed into `Curve`s, and all measurement is done in DXF XY coordinates, independent of zoom or tessellation.
- [DxfReader.cs](src/VibeDxf.Wpf/DxfReader.cs) — ASCII-only parser. Reads all group-code pairs into memory, picks up `$INSUNITS`, then collects `0`-delimited records in ENTITIES and BLOCKS and recursively expands referenced blocks. Unsupported entity types are counted in `DxfDocument.Skipped` and produce a warning after opening. INSERT expansion protects against cycles, depth, array and entity-count limits. Child layer 0 inherits the insertion layer; handles contain the insertion path. `DxfPrimitives.cs` creates text contours, transforms curves and triangulates fills; `DxfReader.Load` caches the triangles in `DxfEntity.FillTriangles` in parallel on the loading thread, so upload doesn't triangulate on the UI thread. Text substitutes Arial; nonuniform transformed arcs and glyph outlines are approximate. POINT coordinates remain exact; their markers are fixed-size in the GPU shader. Polyline bulges become arc `Curve`s.
- [MeasurementTarget.cs](src/VibeDxf.Wpf/MeasurementTarget.cs) — a selection target is either a whole entity or the exact midpoint of one of its straight segments (`MidpointSegment` index). `MidpointIndex` keeps X- and Y-sorted arrays and binary-searches them for hover snapping instead of scanning every entity.
- [DrawingRenderer.cs](src/VibeDxf.Wpf/DrawingRenderer.cs) — Direct3D 11 renderer on a flip-model swap chain. `SetDrawing` uploads the curves once per document into immutable GPU buffers: line segments as a `LineList`, SOLID/text fills as a `TriangleList`, fixed-size POINT crosses as a `LineList` with a point shader, rays/xlines as per-instance data that `RayVS` extends to ±3 NDC around the screen centre, and arcs as per-instance data that the `ArcVS` shader expands into line strips. Arcs are sorted by radius into power-of-two buckets, each drawn with just enough segments for ~¼ px chord error at the current zoom. Coordinates are stored relative to the drawing's centre (`Origin`) so float32 keeps precision. Model and paper space share each buffer as two `Part` ranges with separate origins. The `lineVertexCount`/`rayInstanceCount`/`buckets`… fields describe the model part only. The camera is a general affine (`row0`/`row1`). In layout mode each `DxfViewportWindow` re-draws the model part through `ModelToPaper * camera` under a scissor rectangle, then draws the paper part. A frame only rewrites one dynamic constant buffer (camera + color) and issues the draw calls. Overlays are drawn afterwards with Direct2D/DirectWrite on the same back buffer, in DIPs. HLSL is compiled at startup with `D3DCompiler`.
- [DxfViewport.cs](src/VibeDxf.Wpf/DxfViewport.cs) — a WPF `Border` that holds `SwapChainHost`, an `HwndHost` child window owning the swap chain. The child returns `HTTRANSPARENT` from `WM_NCHITTEST`, so all mouse input (including the wheel) arrives as ordinary WPF events on `DxfViewport`. The viewport owns the camera (`scale`/`offset`, DIPs, y-up world), selection, hover snapping and measurement. Every change calls `Invalidate`, which coalesces into one `RenderNow` per dispatcher pass. Selected entities' outlines are rebuilt in screen space each frame as Direct2D path geometries (3 px strokes). Selection order matters: signed ΔX/ΔY go from the first (orange) target to the second (blue).
- [MainWindow.xaml.cs](src/MainWindow.xaml.cs) — file open, drag-drop, background-thread parsing, and the footer that shows status and measurement.

## Gotchas

- See [SPLINES.md](SPLINES.md) for supported spline data, the 0.0001-unit approximation bound, approximate measurements, and offline visual test reports. `SplineGeometry.cs` flattens NURBS once at load; spline chords must not become midpoint snap targets. Tests write `artifacts/test-report/index.html` with diagrams, actual GPU readbacks, and all test results. Build the solution to discover the xUnit cases in VS Test Explorer. Add new named checks to `Tests/CheckCatalog.cs`; the catalog completeness test catches missing discovery entries.
- The bottom-right Center/Closest toggles belong to the first (orange) and second (blue) selection slots. Only standalone CIRCLE/ARC entities use their underlying circle center; lines, polylines, and explicit midpoints keep their existing behavior. `DxfViewport.FirstStrategy` / `SecondStrategy` immediately recalculate and raise `SelectionChanged` so the footer and connector refresh without reselecting. Offline strategy checks live in [Tests/MeasurementStrategyChecks.cs](Tests/MeasurementStrategyChecks.cs); run the checks with `--no-restore` after dependencies are restored to avoid network access.
- **Tests and demo reference the compiled Wpf library.** Tests/VibeDxf.Checks.csproj compiles only its own *.cs files. No production-source compile links remain. Narrow library friendships allow existing synthetic fixtures/device instrumentation and demo GPU captures; renderer/native handles remain internal. Public hosting/measurement APIs are tested in Tests/LibraryApiChecks.cs.
- **Viewport checks use reflection on private members.** [Tests/ViewportChecks.cs](Tests/ViewportChecks.cs) accesses `DxfViewport`'s `host`, `offset`, `scale` and `hoveredMidpoint` fields, `SwapChainHost`'s auto-property backing field `<Renderer>k__BackingField`, `DrawingRenderer`'s `lineBuffer`/`arcBuffer`/`rayBuffer` and `lineVertexCount`/`rayInstanceCount`, and the `SelectAt(Point, bool)`, `SetHoveredMidpoint(MeasurementTarget)` and `RenderNow()` methods by name. Renaming or changing the signature of any of these breaks the checks at runtime, not at compile time. These checks run on a dedicated STA thread and show a real off-screen window, so they need a GPU or the WARP fallback.
- The checks assert that hover, selection, pan and zoom reuse the same GPU buffers. This is a performance invariant: only `SetDrawing` (a new document, or a renderer re-created on `Loaded`) may upload geometry.
- **Renderer lifetime follows the visual tree, not the HWND.** When the window closes, WPF parks `HwndHost` children instead of destroying them, so `DestroyWindowCore` isn't called. `SwapChainHost` disposes the renderer on `Unloaded` and re-creates it on `Loaded`.
- Don't remove `HTTRANSPARENT` or make the child window disabled. A disabled child drops clicks, and a hit-testable one takes mouse input away from WPF.
- [nuget.config](nuget.config) clears all package sources except nuget.org, because the machine-wide config has a private feed that fails with 401.
- `ALT-F2/` holds a Visual Studio diagnostics session (`.diagsession`) from profiling. It is not source.

- Public primitive tests live in `Tests/PrimitiveChecks.cs`, with `Tests/Fixtures/primitives-and-blocks.dxf`. They are direct xUnit tests (not catalog scenarios) and add GPU captures to the HTML report. Both projects reference the compiled library.

- `DxfHatch.cs` parses hatch paths and clips stored pattern definitions once at load. `Curves` holds measurement/selection boundaries; `RenderCurves` overrides visible strokes, `FillContours` holds solid fill, and `RegionContours` handles both hatch kinds. `RenderDots` uses a small fixed-size GPU cross. Gradient and density-limit cases warn instead of silently showing a wrong fill. Triangulation splits at edge intersections and rejects numerical sliver strips. `Tests/HatchChecks.cs` covers all boundary types, island styles, concavity, dash phases, dots, block transforms, and all 89 public sample hatch instances (model space and all four sheets). It also generates a zoomed GPU atlas in the HTML report. Search the report for a hatch handle to see its orange hatch strokes and stored contour against the white drawing. Sample hatch 95F2 and outline 14C2 are explicitly offset in the source file; do not invent an association to move it.

- `DxfMText.cs` uses WPF `TextFormatter` at load time to shape/wrap native text runs, then extracts vector glyph and decoration geometry for immutable GPU buffers. DXF fractions and stretched/tracked/slanted spans use embedded text objects. It retains DXF baseline spacing and attachment transforms. It supports chunks (group 3 + 1), paragraphs, wrapping, attachments, planar WCS direction/normal, formatting scopes, fractions, height/width/tracking/slant and bold/italic flags with Arial substitution. MTEXT is WCS-based: do not apply the reader's OCS mirror to it a second time. `DxfDocument.RenderingWarnings` reports partial formatting limitations without counting loaded text as skipped. Columns/vertical/3D layouts remain explicit skips. Tests in `Tests/MTextChecks.cs` include GPU captures; `Tests/Fixtures/mtext.dxf` is a public synthetic fixture. The checks/demo consume this source through the compiled library.

- MTEXT tags after group 101 (`Embedded Object`) and group 1001 (XDATA) must not be read as main entity properties. Embedded group 10/20 is a direction, while group 11/21 is a repeated insertion point. `uncommon.dxf` has this layout on all 19 labels; interpreting 11/21 as the axis causes false 34–69 degree rotations. Single embedded columns work; multiple columns remain unsupported. TextFormatter uses WrapWithOverflow so unbreakable CAD labels are not split into individual letters.

- DIMENSION, ARC_DIMENSION and LARGE_RADIAL_DIMENSION expand their anonymous `*D` block like ezdxf does: translate by group 12, apply the OCS mirror, and do not subtract a block base point. Children get `DxfEntity.IsAnnotation`, which `DxfPrimitives.Transform` propagates through nested arrowhead INSERTs. Annotations render normally but are excluded from `DxfViewport.SelectAt` and `MidpointIndex`. POINT records inside dimension blocks are defpoints and are dropped. Missing or empty blocks are counted as skipped. Tests: `Tests/DimensionChecks.cs` with `Tests/Fixtures/dimensions.dxf`.

- `DxfMLeader.cs` builds one display-only (`IsAnnotation`) MULTILEADER entity from CONTEXT_DATA, following ezdxf's render engine. Leader-line vertices are followed by the last leader point, then the dogleg. A closed filled arrow (context 140 size) is drawn only when the first segment exceeds twice that size, and the line starts at the arrow base. MTEXT content goes through `DxfMText.Read`, with alignment 1/2/3 as top-left/center/right attachment and rotation ignored. Spline leaders, custom arrows and block content produce rendering notes. The source is compiled once in the library; tests are in `Tests/MLeaderChecks.cs`.

- `DxfDocument.Entities` is model space only; `DxfDocument.Layouts` holds one `DxfLayout` per sheet tab, sorted by group 71. Names come from OBJECTS LAYOUT records; their AcDbLayout group 330 points to a BLOCK_RECORD. The active layout (`*Paper_Space`) is filled from top-level ENTITIES records with group 67=1. Every other layout is filled from its `*Paper_SpaceN` block records. R12 files without LAYOUT objects get one "Layout". Layouts with no paper-space content besides viewport frames and fewer than two viewports are removed after loading (unused defaults such as Layout1/Layout2), so the tab strip stays hidden for flat drawings. VIEWPORTs become `DxfViewportWindow`s plus a display-only frame entity. The transform follows ezdxf: `paper = center + s·(R(twist)·(P − target) − viewCenter)`, `s = 41/45`, plan views only. **Inactive layouts store viewport ID and status 0**, so the first VIEWPORT of each layout is its sheet view (ID 1 in the active one), and status is only trusted in the active layout. `DxfViewport.ActiveLayout` (−1 = model; the window's tab strip and Ctrl+PgUp/PgDn set it) switches picking, the midpoint index, bounds and the renderer's paper part without re-uploading GPU buffers. Tests: `Tests/LayoutChecks.cs` with `Tests/Fixtures/layout.dxf`; api-cw750 has four sheets.
- ATTRIB records render like ATTDEF text (groups 72/74 alignment) in the coordinate system of the INSERT they follow; invisible (70 bit 1) and empty values draw nothing. LEADER follows ezdxf's `render/leader.py`:
  - vertices, plus a hook line when 73=0 and 75=1;
  - arrow size DIMASZ·DIMSCALE from the DIMSTYLE (TABLES) and ACAD DSTYLE XDATA overrides (`DimStyleOverrides`), with DIMSCALE 0 treated as 1;
  - DIMLDRBLK resolved through the BLOCK_RECORD handle map and expanded as a unit arrow block (tip at origin, body along −X), falling back to a closed filled triangle.

  Leaders and their arrows are `IsAnnotation`.
- `DxfPrimitives.DecodeText` handles \U+XXXX, %%d/p/c, %%nnn, %%%, removes %%u/%%o toggles, and turns caret-encoded control characters (`^I`) into spaces. MTEXT text runs use it too.
- Layers and colors:
  - **Reader:** `DxfDocument.Layers` comes from the LAYER table; on/frozen/plot describe the *saved* state. `DxfColors` resolves entity colors once at load:
    - 420 true color wins, then ACI;
    - 256 or absent is BYLAYER, using the effective layer;
    - 0 is BYBLOCK, the enclosing insert's resolved color, threaded through `Process`/`Expand`/`ExpandDimension`/leader arrows as `blockColor`.

    Source colors remain raw; the renderer lifts them to a luminance floor for the dark background. `DxfEntity.Category` replaces the old annotation flag (`IsAnnotation` is computed: Dimension and up). Each entity's `Group` indexes `DxfDocument.Groups` (layer, category).
  - **Renderer:** vertices and instances carry packed RGBA plus the group index. The vertex shader reads a small dynamic `Buffer<uint>` of group flags (`GroupVisible`, `GroupAnnotation`) and moves hidden primitives out of the clip volume. `SetGroupFlags` and per-viewport freezes (`DxfViewportWindow.FrozenLayers`) only rewrite that table, never the geometry buffers. Annotations draw at 0.45 opacity; model content seen through viewports is not dimmed because it is selectable. Monochrome is a constant-buffer switch.
  - **Viewer and panel:** `DxfViewport` owns layer/category visibility (`SetLayerVisible`, `SetLayersVisible`, `SetCategoryVisible`, `ShowAll`, `ApplySavedLayerState`, `IsolateLayer`, `Monochrome`, `VisibilityChanged`). Hidden entities are excluded from `SelectAt` and the rebuilt `MidpointIndex`. On a sheet, `Pick` tries paper entities first. Inside a viewport window it maps the click through the inverse `ModelToPaper` into model space and uses `modelIndex`, skipping that viewport's `FrozenLayers`. The resulting `MeasurementTarget.Viewport` keeps model coordinates for measurement; overlays map through it, clipped with `PushAxisAlignedClip`. Keep the one-argument `BuildScreenGeometry(curves)`, because ViewportChecks invokes it by reflection. `LayerPanel` (left column beside the HwndHost, `Ctrl+L`) mirrors that state.
  - **Tests:** showcase captures of public drawings call `ShowAll()` first, because api-cw750 saves 13 of its 22 layers off. `Tests/LayerChecks.cs` uses ezdxf's `colors.dxf` and `viewport_frozen_layers.dxf`. Source colors stay raw; renderer/host swatches use DxfDisplayColors.ForDarkBackground.

## Saved model cameras and spatial display

See docs/SAVED-CAMERAS.md. DxfDocument.ModelViews/DefaultModelView expose saved VPORT and named model VIEW cameras; public DxfView restores the saved camera and exposes ActiveModelView plus ModelViewChanged. The desktop View > Model camera menu also offers original XY. The first *ACTIVE VPORT takes precedence over legacy HEADER settings; tiled camera definitions are selected individually. Positive-Z unclipped plan views reuse analytic model GPU ranges through their target/twist transform. Nonplan/perspective/depth-clipped views are display-only and reject model-XY anchors.

DxfSpatialGeometry is immutable XYZ display data, separate from analytic XY query curves. DxfCameraProjection clips segments/polygons before perspective division, applies the saved lens/framing, and emits scene-consistent reversed depth. DrawingRenderer uses float3 display vertices and a D32 depth buffer with GreaterEqual/clear 0 only for spatial ranges; 2D passes disable depth. Line bias is relative to depth, so far perspective edges cannot jump in front of surfaces. GPU geometry stays uploaded across camera switches. Spatial preparation failure must never discard valid original XY geometry: record SpatialGeometryError and reject the affected projected camera instead.

The SAT 400 torus fixture has no topological edges. Its bounded analytic torus mesh is display-only, has no invented query curves/midpoints, and measurements return NoGeometry. Supported straight/elliptical ACIS boundaries retain XYZ for camera display. No general ACIS kernel or orbit/lighting implementation was introduced. Relevant direct checks: SavedCameraChecks, DxfCameraProjectionChecks, TorusChecks, OrthographicViewportChecks and the existing public/API/GPU suites.
## ACIS intersection spline boundaries

DxfAcisSpline.cs admits the explicit binary exact_int_cur 20900 profile and uses positive-weight rational Bezier hull bounds for XYZ flattening and saved parameter trims. DxfSolidProjection recognizes the exact tolerant topology names and validates endpoint differences using the admitted local tolerant vertex bounds without snapping the source curve. See docs/ACIS-SPLINE-BOUNDARIES.md. WashbasinSolidChecks includes numeric/rejection cases and the SHA-verified compressed public sink fixture, asserting all 13 solids plus actual XY/saved-camera GPU captures. This adds boundary coverage, not general ACIS face shading.
